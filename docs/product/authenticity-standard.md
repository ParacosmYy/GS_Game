# 真实性标准

本文定义“更像 KOF”如何验收。这里的接近指工程和体验标准，不指复制商业素材。

## 1. 当前判断

项目目前最大差距集中在：

- 角色肖像不像正式街机角色。
- 角色动作仍像 placeholder 或骨骼假人。
- 视觉帧、判定帧、命中反馈没有完全同源。
- 打击反馈有组件，但没有形成攻击重量矩阵。
- 角色太多，但没有一个样板完整闭环。

因此真实性标准先落到 Ryo。

## 2. Ryo 优先标准

Ryo 必须先达到：

- 选人/HUD 肖像可信。
- idle 有极限流空手道气质。
- walk 不滑、不漂。
- jump 有起跳、滞空、落地节奏。
- stand A 是轻攻击样板。
- stand C 是重攻击样板。
- hurt 有明确受击姿态。
- knockdown 有倒地过程。

## 3. 帧节奏标准

- 所有攻击必须有 startup / active / recovery。
- 视觉帧不能与判定帧脱节。
- active 帧必须能被调试工具看到。
- cancel window 不能靠魔法数字散落。

## 4. 打击反馈标准

至少三档：

- light：短 hitstop、小 spark、小 pushback。
- heavy：较长 hitstop、更大 spark、明显受击、shake。
- special：专属 spark/SFX/位移/残影。

每档反馈必须由 hit event 触发，不得由渲染函数临时决定。

## 5. 操作可见性标准

- 战斗界面必须常驻显示当前角色的招式表，且招式表必须直接读取 `CharacterDefinition.moveList`，禁止使用写死的示例文本。
- 招式表至少要覆盖：常用通常技、至少一到两个核心必杀、DM/大招、爆气说明。
- 爆气必须在界面上明确显示两种入口：标准键位与快捷键。
- 当前项目的标准爆气说明必须同时给出 `K+U` 和 `O`，其中 `K+U` 代表标准输入，`O` 代表快捷爆气。
- 训练模式、战斗界面、角色说明页三者对同一角色的按键说明必须一致，不允许三套文案互相打架。

## 6. 美术标准

- placeholder 只能作为 fallback。
- 正式方向必须是 sprite atlas + manifest。
- 肖像必须有尺寸、来源、fallback、替换路径。
- 角色色彩、轮廓、动作要统一，不能像拼图。

## 7. 参考资料边界

允许：

- 学习 MUGEN/IKEMEN 的数据驱动、状态机、资产工具链。
- 参考公开帧数据和公开机制说明。
- 使用合法原创或明确许可资源。

禁止：

- 复制商业 sprite、音频、肖像。
- 搬运未确认许可的 MUGEN 角色包。
- 把参考源码结构照搬成当前运行时。

## 8. 每轮真实性复盘

每轮必须回答：

- Ryo 哪个体验更像 KOF？
- 玩家第一眼能否看出来？
- 操作时能否感到重量？
- 还有哪个点最不像？
- 下一轮应该补资产、动作、判定还是反馈？
