# 公共基础组件总说明

本文定义本项目后续必须优先沉淀的公共基础组件，以及这些组件与角色内容包、渲染层、输入层、测试工具之间的边界。

## 1. 核心原则

- 先抽公共骨架，再做角色差异。
- 角色只提供数据、资源和少量路由，不重复实现通用流程。
- 一个角色做精的前提，是它的每条链路都能走同一套公共组件。
- 任何新文件如果只是“另一份同构副本”，优先回到公共组件层，不要继续复制。

## 2. 必须优先公共化的能力

### 2.1 Frame Contract

统一动作帧、判定帧、反馈帧、事件标签的 schema。

职责：

- 描述角色动作的统一语言。
- 让 combat、rendering、audio、tools 共享同一份数据语义。
- 为校验器和完整度报告提供稳定输入。

### 2.2 高分辨率帧注册器

统一角色帧集注册、查询、缓存、afterimage、姿态解析。

职责：

- 提供通用注册框架。
- 角色只提供自己的帧集与映射表。
- 避免每个角色自己写一套 highResRender。

### 2.3 命中反馈档位系统

统一 light / heavy / special / DM / SDM / HSDM / MAX 的反馈参数。

职责：

- 让 hitstop、spark、shake、pushback、flash、screen edge 等变成参数化能力。
- 角色差异仅体现在颜色、强度、事件标签和少量特例。

### 2.4 肖像 manifest + 尺寸解析器

统一 select / HUD / VS / win 的尺寸、裁切、缩放、fallback。

职责：

- 保证头像体系一致。
- 避免每个界面自己写裁切逻辑。
- 让角色肖像更容易替换和校验。

### 2.5 输入解析 + 命令缓冲

统一原始按键、方向语义、边沿检测、必杀技识别。

职责：

- 所有角色复用同一套输入采样。
- 角色只负责 motion 到 attack 的映射。

### 2.6 Move List / 招式表模型

统一招式条目的结构、分类、输入显示、文案引用。

职责：

- 训练模式、街机 UI、说明文档复用同一份数据。
- 避免每个界面手写一份招式表。

### 2.7 角色内容包 Schema

统一 `commands / moves / attacks / animations / hitboxes / feedback / portraits / reports` 的结构。

职责：

- 让角色内容可复制。
- 让校验工具能针对单角色做完整度审查。

### 2.8 校验与报告

统一 manifest 校验、Frame Contract 校验、完整度报告、fallback 覆盖率报告。

职责：

- 让“做精一个角色”有可量化标准。
- 避免只凭感觉扩内容。

## 3. 公共组件与角色数据的关系

- `core/` 放 schema、枚举、纯函数。
- `input/` 放输入采样、方向解析、命令缓冲。
- `combat/` 放判定、气槽、资源规则、命中事件。
- `rendering/` 放绘制适配、UI 展示、VFX、肖像渲染。
- `src/content/characters/<id>/` 放角色私有数据。
- `tools/` 放校验器、报告、离线生成与验证脚本。

## 4. 不得重复造轮子的内容

- 角色专属渲染入口。
- 角色专属输入提示面板.
- 角色专属头像裁切规则。
- 角色专属命中反馈流程。
- 角色专属状态机总控。
- 角色专属 manifest 校验逻辑。

## 5. 推荐落地顺序

1. Frame Contract + 校验链。
2. 高分辨率帧注册器。
3. 命中反馈档位系统。
4. 肖像 manifest + 尺寸解析器。
5. 输入解析 + 命令缓冲。
6. 招式表模型。
7. 角色内容包 Schema。
8. 校验与报告。

## 6. 与“先做一个角色做精”的关系

公共组件不是把角色做薄，而是让一个角色可以完整走完：

- 选人
- HUD
- VS
- 战斗
- 命中反馈
- 胜利
- 报告

只有当这条链路全都复用同一套公共组件时，样板角色才真正成立。
