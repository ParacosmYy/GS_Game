# 迭代工作区

这里是后续所有“需要继续迭代”的统一收纳区。

## 作用

- 收集下一轮要做的事情。
- 暂存尚未进入正式实现的方案、草案和回归记录。
- 作为交接给下一位 AI 的固定入口。
- 让迭代相关文件不再散落在仓库根目录或各处文档之间。
- 所有待办最好能追溯到 [KOF 差距矩阵](../product/kof-gap-matrix.md) 的某一项差距，避免记录一堆无法验收的想法。
- 当前 Phase 2 的待办优先围绕流程仪式感、多角色内容包、UI/HUD、稳定性和工具链收口。

## 目录约定

```text
docs/iteration/
├── README.md          # 说明这个工作区怎么用
├── active.md          # 当前正在推进的迭代清单与目标
├── backlog.md         # 后续准备做、但还没进入本轮的事项
├── handoff.md         # 交接给下一轮 AI 的说明
└── archive/           # 已完成迭代的历史记录
```

## 使用规则

- `active.md` 只放当前这一轮要做的内容。
- `backlog.md` 只放尚未进入本轮的候选项。
- `handoff.md` 只放给下一位 AI 的固定提示、注意事项和未完成项。
- `archive/` 只放已完成的历史记录，不参与当前决策。
- 生产代码、资源文件、工具脚本不要放进这里。
- 如果某个迭代项已经足够稳定，就从这里迁移到正式的 `docs/process/`、`docs/product/` 或 `docs/architecture/` 中。

## 约束

- 所有后续“继续迭代”的内容，优先写入这里，而不是散落到别的文档里。
- 如果新增的迭代文档与这里冲突，以 `AGENTS.md` 和 `CLAUDE.md` 的规则为准。
- 这里不是临时聊天记录区，而是面向持续执行的工作区。
